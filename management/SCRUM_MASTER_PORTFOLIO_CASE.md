# Scrum Master Portfolio Case: Archives VI

## Project Context

Archives VI is a portfolio web application dedicated to GTA VI mysteries,
theories, easter eggs and community investigations.

The project is built with React, Vite, TypeScript and Styled Components. It is
currently in MVP foundation stage, with the design system and documentation
being established before broader feature development continues.

## Product Vision

The product vision is to create a central community archive where players can
discover, document and discuss mysteries from the GTA VI universe.

The platform should feel like a premium investigation board: atmospheric,
structured and useful for both casual visitors and deep community researchers.

## Agile Approach

The project is organized into staged delivery:

- Sprint 1: technical and visual foundation.
- Sprint 2: architecture cleanup.
- Sprint 3: design system foundation.
- Documentation Sprint: product and Scrum artifact hardening.
- Sprint 4: Home MVP data and components.

The backlog is arranged by epics, features, user stories, technical tasks,
documentation work, research and technical debt.

## Sprint Planning

Sprint planning uses:

- Product goals from the roadmap.
- Definition of Ready.
- Dependencies between design system, data model and Home sections.
- Story point estimates.
- Risk and technical debt visibility.

The next recommended sprint is Sprint 4: Home MVP Data and Components.

## Backlog Management

The backlog separates:

- Completed foundational work.
- Ready next-sprint work.
- Future backlog.
- Research tasks.
- Technical debt.

ClickUp-ready fields include priority, sprint, story points, dependencies,
acceptance criteria, definition of done, component and area.

## Use of AI Tools

AI assistance is used as a product and engineering collaborator for:

- Documentation drafting.
- Backlog structuring.
- Sprint planning support.
- Architecture review.
- Component implementation support under human direction.

AI output is grounded in the repository state and reviewed against explicit
project rules before use.

## Engineering Practices

Current practices:

- React + Vite + TypeScript.
- Styled Components as official styling solution.
- Theme-token-based styling.
- Folder-based UI primitive structure.
- Conventional Commits.
- Build validation after code changes.
- Documentation updates for architecture and design system decisions.

## Metrics to Track

Delivery metrics:

- Sprint completion rate.
- Planned versus completed story points.
- Blocked task count.
- Technical debt trend.

Product metrics:

- Home MVP completion.
- Case card engagement.
- Case detail read depth.
- Community submission readiness.

Engineering metrics:

- Build success rate.
- Reusable component adoption.
- Number of hardcoded UI instances replaced by primitives.
- Accessibility issues found and resolved.

Portfolio metrics:

- Documentation completeness.
- Recruiter review readiness.
- Clarity of architecture decisions.
- Demonstrable Scrum artifacts.

## Lessons Learned

- Stabilizing architecture before feature growth reduces rework.
- A design system should be established before scaling UI pages.
- Documentation is part of delivery, not an afterthought.
- Generated UI assets need a cleanup strategy to avoid long-term ambiguity.
- Future framework migration should be triggered by product readiness, not
  excitement alone.
